Le constat

Vous regardez vos agents écrire à toute vitesse… sans oser leur confier une vraie mission.

Ce que font la plupart des devs

  • Des prompts vagues — « améliore ce code » — et des résultats approximatifs qu'il faut corriger soi-même
  • Des merges les yeux fermés, sans lire le diff — et des régressions qui sortent en prod
  • Des tests supprimés ou vidés par l'agent, sans que personne le voie
  • Des agents qui réécrivent toute la codebase « au passage » — et cassent ce qui marchait
  • Des budgets tokens qui explosent sur des missions mal cadrées
  • Plusieurs agents qui se marchent dessus sur le même repo

Résultat : l'agent impressionne au démo, mais la confiance ne vient jamais — et le code, lui, se dégrade en silence.

Ce que vous allez faire

  • Cadrer chaque mission dans une fiche de tâche avant d'ouvrir l'agent
  • Missionner avec un prompt en 7 blocs que l'agent comprend du premier coup
  • Relire le diff comme un expert et repérer les 7 signatures du code d'agent
  • Imposer le garde-fou tests : test d'abord, code ensuite, CI obligatoire
  • Garder un budget et un périmètre fermes à chaque mission
  • Orchestrer plusieurs agents sans conflits ni perte de contrôle

Résultat : vous déléguez l'écriture, vous gardez les décisions.

Le programme — 6 modules

De la première mission au chef d'orchestre

Chaque module : une leçon dense, un exemple réel, un exercice à faire en 15-30 minutes.

01
Choisir

Choisir son agent (et son modèle)

CLI, IDE ou agent autonome : les critères qui comptent vraiment — contrôlabilité, transparence, coût par mission, fenêtre de contexte. Le bon choix selon votre profil (dev en poste, alternant, solopreneur), avec les chiffres réels d'une mission typique.

Livrables : grille de choix · tableau comparatif · calcul de budget

02
Cadrer

Setup d'un repo de travail

Le terrain d'atterrissage de chaque mission : un fichier de contexte (AGENTS.md) que l'agent lit automatiquement, des branches propres, un budget tokens, des permissions de commandes et un environnement reproductible.

Livrables : modèle d'AGENTS.md · conventions git · garde-fous de budget

03
Missionner

Le prompt de mission parfait

L'anatomie d'une mission que l'agent comprend du premier coup : rôle, objectif mesurable, périmètre, contraintes, définition de fini, livrables, format. Le pattern spec-first et les 6 erreurs qui coûtent des heures.

Livrables : template de prompt de mission · fiche de tâche · boucle de feedback

04
Vérifier

Review des changements

Lire un diff efficacement, repérer les 7 signatures du code d'agent (sur-ingénierie, hallucinations d'API, tests vidés, refactorisations non demandées…), et valider sans merger les yeux fermés. Quand dire non, et comment.

Livrables : checklist de review · workflow de validation en 5 étapes

05
Sécuriser

Le garde-fou tests

Les tests comme contrat de délégation : test-first avec l'agent, définition de fini vérifiable, CI comme arbitre, détection des tests creux. Le filet qui transforme l'agent en collaborateur fiable.

Livrables : contrat de tests à coller dans chaque prompt · hiérarchie du filet

06
Orchestrer

Monter une équipe d'agents

Quand une mission dépasse une journée : spécialiser les rôles (implémenteur, reviewer, testeur), ordonnancer les fiches de tâches, faire relire les agents entre eux, et arbitrer les conflits avec git comme juge de paix.

Livrables : graphe de mission · revue croisée · rétrospective d'équipe

Extrait — module 3

Le prompt de mission qui change tout

Un extrait réel de la formation : la mission « ajouter le paiement Stripe » rédigée avec les 7 blocs. À copier, à adapter, à utiliser dès ce soir.

prompt-mission.md — mission PAIEMENT-STRIPE 
# Mission PAIEMENT-STRIPE — ajouter le paiement par carte

Rôle : développeur senior sur le repo caissevite. Stack : Node 20, Express, SQLite.
Tu travailles sur la branche feature/paiement-stripe (déjà créée).

Objectif (mesurable) : un client peut payer une commande par carte.
Critère de réussite : le parcours complet (créer la commande → payer → confirmer)
passe les 5 tests d'intégration du fichier tests/paiement.test.js.

Périmètre : fichiers autorisés : src/paiement/, src/routes/,
db/migrations/, tests/paiement.test.js. Interdit : toucher à
src/front/, package.json (sauf ajout de stripe), modifier les tests existants.

Contraintes : clé API Stripe lue depuis process.env.STRIPE_SECRET_KEY
(jamais en dur). Erreurs retournées en JSON {error: "…"}. Style : async/await.

Définition de fini : ✅ 5 tests d'intégration verts · ✅ npm run lint ✅
· ✅ npm run typecheck ✅ · ✅ migration SQLite appliquée
· ✅ aucun test existant modifié · ✅ résumé des changements + risques en fin de mission.

Livrables : un commit atomique par étape, messages en
conventional commits (feat/fix/test), puis un diff résumé à relire.

Format : réponse finale en français, max 250 mots : ce qui a été fait,
ce qui n'a pas été fait, les risques restants. Ne pas écrire de code hors mission.

FAQ

Questions fréquentes

Faut-il savoir coder pour suivre la formation ?

Oui, un minimum — c'est une formation pour développeurs, alternants et solopreneurs techniques. Pas besoin d'être senior : savoir lire du code, lancer des commandes et comprendre ce qu'est un test suffit. Le module 2 part de zéro sur le setup.

Quel agent faut-il choisir ?

La formation est volontairement outil-agnostique : le module 1 vous donne la grille de choix (contrôlabilité, transparence, coût, contexte) et un tableau comparatif des familles d'agents — CLI, IDE, agents autonomes. Vous repartez avec le bon choix pour VOTRE profil, pas pour la hype.

Combien de temps pour en voir les effets ?

La promesse : en 2 h, vous déléguez une mission complète à un agent sans perdre le contrôle. Les modules 1 à 3 se suivent en une soirée ; les modules 4 à 6 se pratiquent sur vos vraies missions de la semaine.

Je n'ai encore jamais utilisé d'agent de code. C'est un problème ?

Non — c'est même un avantage : vous n'aurez pas à désapprendre les mauvais réflexes. Le module 1 compare les options sans présupposé, et chaque exercice se fait sur un repo d'entraînement simple.

Comment se passe la livraison ?

Vous passez commande via le formulaire, vous recevez un email de confirmation avec les instructions de paiement (virement ou message privé). Dès réception du paiement, vous recevez la formation en PDF et, selon l'offre, les 5 templates de prompts. Comptez moins de 24 h.

Comment se déroule la session du Pack Mentor ?

Après votre commande, nous réservons ensemble un créneau d'1 h en visio. Vous m'apportez votre setup et une mission réelle : nous la cadrons, nous rédigeons le prompt ensemble, puis nous faisons le retour à chaud sur les résultats. Session enregistrée, replay inclus.

Et si la formation ne me convient pas ?
